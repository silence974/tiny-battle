# 阶段栏折叠交互设计

## 意图

让玩家可以收起不需要查看的阶段内容，减少阶段栏占用；当阶段再次进入，或当前阶段从“不是自己行动”变成“轮到自己行动”时，界面自动展开并明确提示可操作。

## 范围

- 七个阶段行都支持点击标题区域折叠/展开；点击只改变界面状态，不改变引擎规则、通知队列或命令。
- 每个阶段独立维护折叠状态；折叠只作用于当前浏览器席位。
- 阶段切换到新阶段时自动展开该阶段。
- 同一阶段的普通状态同步不强制展开；只有“非自己→自己”的行动边沿才自动展开并更新可操作提示。
- 当前阶段没有可操作内容时也允许折叠，保持阶段栏行为一致。

## 非目标

- 不折叠顶部阶段横幅、阶段摘要或全局提示。
- 不改变 `purchase`/`action` 的可操作判断，不绕过阶段提示播放期间的锁定。
- 不把手动折叠状态写入服务器或跨设备同步。

## 实现方案

保持现有 `.phase-step` DOM 和工业控制台视觉语言。为阶段标题增加可访问按钮，使用 `aria-expanded`、`aria-controls` 和阶段行的折叠 class 控制阶段内容；状态存放在客户端 `collapsedPhases` 集合。

`renderPhaseGuide(snapshot)` 比较上一次阶段、上一次是否轮到当前席位和本次状态：

1. 阶段变化：展开新阶段并清除该阶段的手动折叠标记。
2. 阶段未变且“非自己→自己”：展开当前阶段，显示“轮到你，可操作”的提示。
3. 其他同步：保留用户手动折叠状态。

阶段标题按钮在展开/折叠后只重新渲染阶段行的可见内容，不影响已有 `renderActions()`、`renderPurchaseActions()` 或阶段通知队列。移动端沿用同一状态和按钮语义。

## 验收与回归

- 点击标题可展开，再次点击可折叠；`aria-expanded` 与视觉状态同步。
- 阶段切换后新阶段自动展开。
- 当前席位在同阶段由等待变为可操作时自动展开并显示操作提示。
- 当前席位手动折叠后，普通同阶段 snapshot 不会重新展开；下一次重新轮到自己时会展开。
- 非当前席位的同步不会抢夺手动折叠状态。
- 购牌/行动按钮仍遵守现有合法动作和提示播放锁定；全套 `npm test`、脚本语法检查和浏览器冒烟通过。
