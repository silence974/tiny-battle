# 312 行动入口与建造交互设计

## 意图

行动阶段固定展示建造、派遣、招募三类入口；无可执行行动时入口置灰；另置“跳过”控制，表示跳过本轮剩余行动。顶部显示当前玩家剩余 AP 与总 AP。部署兵力归入派遣入口的子流程，不能因入口收敛而失去可达性。建造提供拖牌落点和先选格再选牌两条等价路径，最终都进入同一个待确认状态。

## 规则与约束

- 建造目标必须是已探索、普通陆地、无建筑、非黑色区域，并且与该玩家已掌控区域正交相邻。
- 合法落点由引擎 `legalActions()` 产生；前端不自行放宽规则，命令执行时再次校验。
- 确认前不扣资源、不消耗 AP、不发送命令；确认只提交一个既有 `build` 命令。
- 拖动和点击路径都使用同一份 `{ building, at, action }` 待确认状态；目标或卡牌改变时只更新预览。
- 拖动使用 Pointer Events，鼠标与触控共用；合法格以黄色状态视觉提示，拖动卡牌显示半透明随手预览。
- 建造卡不可用时降灰、不可点击、不可键盘选中，并设置 `aria-disabled`；不新增解释性文案。
- 离开行动阶段、状态刷新失效、取消或提交失败时清理所有预览与选中状态。

## 派遣与招募交互

- 派遣入口同时保留 `dispatch` 与 `deploy`：后备兵部署以可执行子行动呈现，不因入口收敛而隐藏。
- 选择派遣后，非合法起点降灰；起点锁定后只开放路径末端相邻格，不能重复经过既有路径格。
- 再次点击当前末端或点击“确认终点”锁定路线；路径整体高亮。点击路径上的己方驻兵格可打开详情，详情中的 `− / +` 调整沿路线选兵；右侧汇总显示兵力、战力、产能，至少一名兵员后才可确认。
- 确认派遣后播放短促移动反馈；未探索终点保留地图上的战斗状态标记，由引擎结算。
- 招募只在引擎返回 `recruit` 时出现；资格按当前状态判断：拥有己方控制、已探索且有驻兵的有效兵营即可启用，行动阶段新获得并驻兵的兵营当轮也可招募；表格每行只显示兵种、战力、产能和单个消耗；一次只选择一种兵种，数量 1–3、总消耗和确认控件统一放在表格外，确认后才提交。

## 方案取舍

- 采用现有行动区上的类型入口，不把所有具体目标平铺；弹窗会打断棋盘拖放，直接坐标列表不符合用户要求。
- 派遣入口承载派遣与部署子流程并复用现有合法动作集合，招募以同一行动区的选择表格实现，建造实现完整的目标/卡牌选择与确认流程。

## 非目标

- 不修改资源成本、AP 数值或派遣路线规则；招募单次上限锁定为当前 312 配置的 3 个单位。
- 不新增建造说明文本，不改变服务器协议。
