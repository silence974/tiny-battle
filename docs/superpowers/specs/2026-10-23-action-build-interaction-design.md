# 312 行动入口与建造交互设计

## 意图

行动阶段只展示当前可用的建造、派遣、招募三类入口，另置“结束行动”控制；顶部显示当前玩家剩余 AP 与总 AP。部署兵力归入派遣入口的子流程，不能因入口收敛而失去可达性。建造提供拖牌落点和先选格再选牌两条等价路径，最终都进入同一个待确认状态。

## 规则与约束

- 建造目标必须是已探索、普通陆地、无建筑、非黑色区域，并且与该玩家已掌控区域正交相邻。
- 合法落点由引擎 `legalActions()` 产生；前端不自行放宽规则，命令执行时再次校验。
- 确认前不扣资源、不消耗 AP、不发送命令；确认只提交一个既有 `build` 命令。
- 拖动和点击路径都使用同一份 `{ building, at, action }` 待确认状态；目标或卡牌改变时只更新预览。
- 拖动使用 Pointer Events，鼠标与触控共用；合法格以黄色状态视觉提示，拖动卡牌显示半透明随手预览。
- 建造卡不可用时降灰、不可点击、不可键盘选中，并设置 `aria-disabled`；不新增解释性文案。
- 离开行动阶段、状态刷新失效、取消或提交失败时清理所有预览与选中状态。

## 方案取舍

- 采用现有行动区上的类型入口，不把所有具体目标平铺；弹窗会打断棋盘拖放，直接坐标列表不符合用户要求。
- 派遣入口承载派遣与部署子流程并复用现有合法动作集合，招募先保留类型入口，建造先实现完整的目标/卡牌选择与确认流程。

## 非目标

- 不修改资源成本、AP 数值、派遣路线或招募规则。
- 不新增建造说明文本，不改变服务器协议。
